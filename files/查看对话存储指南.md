# 查看对话存储指南

## 📋 如何查看对话是否已存储到数据库

有几种方法可以查看对话是否已保存到 Supabase 数据库：

---

## 方法 1: 浏览器控制台（推荐）

### 1. 打开浏览器开发者工具
- 按 `F12` 或 `Cmd+Option+I` (Mac) / `Ctrl+Shift+I` (Windows)
- 切换到 **Console（控制台）** 标签

### 2. 查看日志输出

发送消息后，控制台会显示以下信息：

#### ✅ 成功保存的日志：
```
✅ 消息已保存到数据库: { id: '...', role: 'user', ... }
✅ AI 消息已保存到数据库: { id: '...', role: 'ai', ... }
```

#### ❌ 保存失败的日志：
```
Error creating message: { error: {...}, message: '...' }
Error updating message: { error: {...}, message: '...' }
```

### 3. 检查 Supabase 连接状态

查看控制台是否有以下警告：
- 如果看到：`Missing Supabase environment variables. Database features will be disabled.`
  - 说明 Supabase 未配置，数据不会保存到数据库（会使用 localStorage）

---

## 方法 2: Supabase Dashboard（最直观）

### 1. 登录 Supabase Dashboard
访问：https://app.supabase.com

### 2. 选择你的项目

### 3. 查看数据库表

在左侧菜单中选择 **Table Editor**，然后查看以下表：

#### 📊 `conversations` 表
- 查看所有对话记录
- 字段：
  - `id` - 对话 ID
  - `user_id` - 用户 ID
  - `title` - 对话标题
  - `created_at` - 创建时间
  - `updated_at` - 更新时间

#### 💬 `messages` 表
- 查看所有消息记录
- 字段：
  - `id` - 消息 ID
  - `conversation_id` - 所属对话 ID
  - `user_id` - 用户 ID
  - `role` - 角色 (`user` 或 `ai`)
  - `content` - 消息内容
  - `timestamp` - 时间戳
  - `created_at` - 创建时间

#### 📝 `notes` 表
- 查看所有笔记记录
- 字段：
  - `id` - 笔记 ID
  - `conversation_id` - 所属对话 ID
  - `title` - 笔记标题
  - `content` - 笔记内容
  - `updated_at` - 更新时间

#### 📎 `uploaded_files` 表
- 查看所有上传的文件
- 字段：
  - `id` - 文件 ID
  - `conversation_id` - 所属对话 ID
  - `name` - 文件名
  - `type` - 文件类型
  - `content` - 文件内容

### 4. 使用 SQL Editor 查询

在 **SQL Editor** 中执行以下查询：

```sql
-- 查看所有对话
SELECT * FROM conversations ORDER BY updated_at DESC;

-- 查看特定用户的所有对话
SELECT * FROM conversations 
WHERE user_id = 'your-user-id-here'
ORDER BY updated_at DESC;

-- 查看所有消息
SELECT * FROM messages ORDER BY timestamp DESC LIMIT 50;

-- 查看特定对话的所有消息
SELECT * FROM messages 
WHERE conversation_id = 'your-conversation-id-here'
ORDER BY timestamp ASC;

-- 统计消息数量
SELECT 
  conversation_id,
  COUNT(*) as message_count,
  COUNT(CASE WHEN role = 'user' THEN 1 END) as user_messages,
  COUNT(CASE WHEN role = 'ai' THEN 1 END) as ai_messages
FROM messages
GROUP BY conversation_id;
```

## 方法 3: 浏览器 Network 标签

### 1. 打开浏览器开发者工具
- 切换到 **Network（网络）** 标签

### 2. 发送一条消息

### 3. 查看网络请求

查找以下请求：

#### ✅ Supabase 请求：
- 请求 URL 包含 `supabase.co`
- 方法：`POST`（创建）或 `PATCH`（更新）
- 查看：
  - **Request Payload** - 发送的数据
  - **Response** - 服务器响应（成功返回数据，失败返回错误）

#### 🔍 常见请求：
- `POST /rest/v1/messages` - 创建消息
- `PATCH /rest/v1/messages?id=eq.xxx` - 更新消息
- `POST /rest/v1/conversations` - 创建对话
- `GET /rest/v1/conversations` - 获取对话列表

## 🐛 常见问题排查

### 问题 1: 没有看到保存日志

**可能原因：**
- Supabase 未配置（检查 `.env` 文件）
- 代码中未调用保存函数
- 保存失败但错误被静默处理

**解决方法：**
1. 检查 `frontend/.env` 文件是否有 `VITE_SUPABASE_URL` 和 `VITE_SUPABASE_ANON_KEY`
2. 检查浏览器控制台是否有错误信息
3. 检查代码中是否调用了 `createMessage()` 函数

### 问题 2: 保存失败

**可能原因：**
- RLS（Row Level Security）策略问题
- 用户未登录
- 数据库表不存在
- 权限不足

**解决方法：**
1. 检查 Supabase Dashboard 中的 RLS 策略
2. 确认用户已登录（`auth.users` 表中有用户记录）
3. 确认数据库表已创建（查看 `数据库部署说明.md`）
4. 检查错误日志中的具体错误信息

### 问题 3: 数据保存在 localStorage 而不是数据库

**可能原因：**
- Supabase 未配置
- 环境变量未加载

**解决方法：**
1. 检查 `frontend/.env` 文件
2. 重启前端开发服务器
3. 检查控制台是否有 Supabase 配置警告
