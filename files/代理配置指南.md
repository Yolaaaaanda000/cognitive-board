# 代理配置指南

## 🔍 问题：无法连接到 Gemini API

如果遇到 "无法连接到 Gemini API 服务器" 的错误，通常是因为：

1. **在中国大陆**：无法直接访问 Google API，需要配置代理
2. **代理未配置**：虽然代理软件在运行，但后端代码没有配置代理

## 📋 配置步骤

### 第一步：找到代理软件的端口号

#### 方法 1: 在代理软件中查看
1. 打开你的代理软件（V2Ray、Clash、Shadowsocks 等）
2. 找到 **"HTTP 代理端口"** 或 **"HTTP Port"**
3. 常见端口：
   - **V2Ray**: 8118 或 10809
   - **Clash**: 7890
   - **Shadowsocks**: 1080
   - **其他**: 查看软件设置

#### 方法 2: 在终端中检测
在终端中运行以下命令，查找正在监听的代理端口：

```bash
# 检测常见代理端口
lsof -i :8118 -i :7890 -i :10809 -i :1080 2>/dev/null
```

### 第二步：配置后端环境变量

在 `backend/.env` 文件中添加代理配置：

```env
# API Key（必需）
GEMINI_API_KEY=your_api_key_here
# 或使用
API_KEY=your_api_key_here

# 代理配置（如果需要代理）
# 根据你的代理软件端口，选择以下配置之一：

# 如果端口是 8118 (V2Ray 常见)
HTTPS_PROXY=http://127.0.0.1:8118
HTTP_PROXY=http://127.0.0.1:8118

# 如果端口是 7890 (Clash 常见)
# HTTPS_PROXY=http://127.0.0.1:7890
# HTTP_PROXY=http://127.0.0.1:7890

# 如果端口是 10809 (V2Ray 常见)
# HTTPS_PROXY=http://127.0.0.1:10809
# HTTP_PROXY=http://127.0.0.1:10809
```

**注意**：
- 将 `your_api_key_here` 替换为你的实际 API Key
- 根据你的代理软件端口，只保留一个 `HTTPS_PROXY` 配置
- 端口号必须与代理软件中显示的端口一致

### 第三步：测试代理是否工作

在终端中测试代理：

```bash
# 替换为你的实际端口
curl -x http://127.0.0.1:8118 https://www.google.com

# 如果返回 HTML 内容，说明代理工作正常
# 如果返回错误，检查：
# 1. 代理软件是否运行
# 2. 端口号是否正确
```

### 第四步：重启后端服务器

修改 `.env` 文件后，**必须重启后端服务器**才能生效：

```bash
cd backend
# 停止当前服务器（Ctrl+C）
# 然后重新启动
npm run dev
```

## 🔧 验证配置

启动后端服务器后，查看控制台输出：

### ✅ 配置成功的提示：
```
✅ 代理设置已启用: { HTTPS_PROXY: 'http://127.0.0.1:8118', ... }
```

### ⚠️ 未配置代理的提示：
```
ℹ️ 未配置代理，使用直接连接
💡 提示：如果无法连接 Google API，请在 backend/.env 文件中配置代理
```

## 📝 完整示例

### 示例 1: V2Ray 代理（端口 8118）
`backend/.env`:
```env
GEMINI_API_KEY=your_api_key_here
HTTPS_PROXY=http://127.0.0.1:8118
HTTP_PROXY=http://127.0.0.1:8118
```

### 示例 2: Clash 代理（端口 7890）
`backend/.env`:
```env
GEMINI_API_KEY=your_api_key_here
HTTPS_PROXY=http://127.0.0.1:7890
HTTP_PROXY=http://127.0.0.1:7890
```

### 示例 3: 不需要代理（网络可以直接访问 Google）
`backend/.env`:
```env
GEMINI_API_KEY=your_api_key_here
# 不配置 HTTPS_PROXY，使用直接连接
```

## ❓ 常见问题

### Q1: 如何确认代理软件是否运行？
- 检查代理软件的状态（应该显示"已连接"或"运行中"）
- 在浏览器中测试是否可以访问 Google
- 查看代理软件的系统托盘图标

### Q2: 代理端口在哪里找？
- **V2Ray**: 设置 → HTTP 代理 → 端口
- **Clash**: General → Port → HTTP Port
- **Shadowsocks**: 本地设置 → 本地端口

### Q3: 配置后还是无法连接？
1. 确认 `.env` 文件在 `backend` 目录下
2. 确认环境变量名称正确（`HTTPS_PROXY`，不是 `HTTPS_PROXY_`）
3. 确认端口号正确（与代理软件显示的端口一致）
4. **确认已重启后端服务器**
5. 查看后端控制台是否有代理启用的提示

### Q4: 代理需要用户名密码怎么办？
如果代理需要认证，在 URL 中包含用户名和密码：
```env
HTTPS_PROXY=http://username:password@127.0.0.1:8118
```

### Q5: 如何确认代理是否工作？
在终端测试：
```bash
# 测试 HTTP 代理
curl -x http://127.0.0.1:你的端口 https://www.google.com

# 如果返回大量 HTML 内容，说明代理工作正常
# 如果返回错误或超时，说明代理未运行或端口错误
```
